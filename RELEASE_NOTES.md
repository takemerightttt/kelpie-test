# Release note - импорт выписки

**Разрешения.** Новых разрешений фрагмент не требует. Файл выбирается системным picker
(iOS - Files, Android - Storage Access Framework), доступ к нему временный и только к выбранному
файлу. `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE` и `SYSTEM_ALERT_WINDOW`, которые шаблон
добавляет по умолчанию, заблокированы в `app.json` (`blockedPermissions`). Остаются `INTERNET`
(API) и `VIBRATE` (из React Native по умолчанию).

**Сеть.** Для тестового mock включены cleartext HTTP на Android (`usesCleartextTraffic`) и
`NSAllowsLocalNetworking` на iOS. В production - только HTTPS, обе настройки убрать.

**Где остаются копии файла.**

0. Системная копия picker в `tmp/<bundleId>-Inbox` (только iOS) - удаляется сразу после локальной
   проверки файла и при каждом старте.
1. Временная копия picker в кэше приложения - сразу после успешной локальной проверки переносится
   в `Documents/imports/<key>` (кэш система может очистить, пока пользователь на экране
   подтверждения); при отказе проверки удаляется сразу, при отмене удаляется перенесённая копия.
2. `Documents/imports/<key>` - удаляется, как только сервер подтвердил job (202 или найден по
   ключу), при отказе сервера и при «Start over». Остаётся, только пока исход POST неизвестен - чтобы
   можно было повторить с теми же байтами.
3. В AsyncStorage хранится только состояние операции (ключ, jobId, статус, имя файла для экрана) -
   без байтов и без результатов отчёта (мерчанты, суммы): они только в памяти, после перезапуска
   приложение заново берёт их с сервера.

**Как очистить данные.** «Start over» / «New import» удаляет копию и состояние. Удаление
приложения на Android удаляет всё: бэкап приложения отключён (`allowBackup=false`), копия и
состояние не уходят в Google Auto Backup. На iOS папка `Documents` попадает в iCloud-бэкап: при
восстановлении из бэкапа копия может вернуться; при старте приложение удаляет все копии в
`Documents/imports/`, не относящиеся к текущей операции. Серверные данные - кнопкой удаления,
подтверждение только по `status=deleted`.

**Что остановит rollout.**

- Рост числа импортов на одного пользователя/ключ (`newJobs > 1` на один ключ) - признак двойной отправки.
- Ошибки 409 на POST - ключ переиспользован с другими байтами.
- Отказы удаления (DELETE 5xx) выше порога или jobs, «застрявшие» в deleting.
- Любое появление имени файла/описаний в логах или аналитике.

**Что требует нового бинарника, а не JS/OTA.** Изменения `app.json` (разрешения, cleartext/ATS,
bundle id), добавление или обновление нативных модулей (`expo-file-system`,
`expo-document-picker`, AsyncStorage), смена SDK Expo. Логика в `src/` (правила, тексты, экраны)
может идти через OTA.

**Проверенные ОС.** См. таблицу в README - заполняется по фактическому запуску.
